# scientific-research-assistant v1.0: release candidate

Stabilisation sprint, 2026-10-26, for use on 2026-10-27. Nothing is committed.

**Verdict:** ready for practical use tomorrow, with one setup step: restart Claude Code (or open `/hooks`) so the execution hook loads. No release blockers are open.

**Finalisation, after the user approved v1.0:**
- pandoc is installed in the root `.venv` (`pypandoc_binary==1.17`, pandoc 3.9, gitignored) and is found before any other project's venv.
- `manuscript check` warns `final_outdated` when `final/` no longer matches the approved sources. It never rebuilds or deletes those files.
- Tests: 275 pass on Python 3.14 and 3.11.

## 1. What changed in this sprint

| Change | Why | Kind |
| --- | --- | --- |
| The hook blocks through JSON `permissionDecision: "deny"` with exit 0, and the settings command ends in `\|\| true` | Python exits 2 when it cannot find its script, and exit 2 means "block". A wrong hook path would have blocked **every** shell command. | Release blocker, fixed |
| `project run` resolves a relative interpreter path (`.venv/Scripts/python.exe`) against the project folder | On Windows the run failed to start (exit 127) for any project that uses its own venv | Release blocker, fixed |
| `manuscript build --final` refuses when pandoc or the browser is missing | It reported a FINAL build with no DOCX or PDF | Release blocker, fixed |
| Run manifest `runs/run-<stamp>.json` (`scripts/sra/runmanifest.py`) | Priority 2: command, exit status, UTC start and finish, Python version and executable, every installed package version, git revision and dirty state, approval versions and decision hashes, input and output hashes. Its SHA-256 is stored in the completion record. | New, minimal |
| `--input` on `project run` | Data-file hashes in the manifest | New |
| `checkpoint propose --option` (saved, and listed by `checkpoint show`) | In a fresh session, "option 1" could only be resolved by reading an old transcript | Usability fix |
| Two runs in the same second get separate log and manifest files | The second run overwrote the first one's log | Fix |
| Docs: `QUICKSTART.md`, options at decisions, the hook's limits, the run manifest; root `CLAUDE.md` and README updated | Priority 4 | Docs |

## 2. Release-readiness checklist

### Verified

- [x] **Offline tests:** 274 pass on Python 3.14 and 3.11.
- [x] **Approvals enforced:**
  - Gate order, version binding, stale after a change, and never approved for the user (unit tests).
  - A doubtful reply records nothing (fresh `claude -p` session).
- [x] **Gates persist across fresh sessions:**
  - Session A, in plain language: created the project, proposed scope with 4 options, and stopped.
  - Session B, a new process: "Approve option 1" was recorded with the user's words, and the session stopped before the question gate.
- [x] **The hook loads in a fresh Claude Code process and blocks** a direct `python analysis.py` through both the Bash tool and the PowerShell tool. The output file was never written.
- [x] **The hook fails open:** a missing hook script exits 0.
- [x] **The only toolkit command that runs project code is `project run`,** and it enforces methodology and execution approval. Every other command searches, checks or renders.
- [x] **Run manifest:** written, hash-bound and tested. It also appeared correctly in the end-to-end demo.
- [x] **Paper flow in plain language across sessions:**
  - "I'd like the final DOCX and PDF": the session found the manuscript stale, showed the one changed sentence and flagged the outdated `final/` folder. It proposed v2 and stopped.
  - "I approve manuscript v2" in a new session: the approval was recorded and `final/` was built with docx, pdf, md and `MANIFEST.json`.
- [x] **The QUICKSTART example was run as written.** With pandoc it produced the final DOCX and PDF, checked visually. Without pandoc the final build now refuses.
- [x] **Live services:** OpenAlex, arXiv, Crossref, PubMed, Hugging Face, GitHub and Zenodo respond. Semantic Scholar is rate-limited without a key; the toolkit carries on without it.
- [x] **Build tools:** pandoc 3.9 comes from the root `.venv`, under both Python 3.14 and 3.11. Edge is found. A real final DOCX and PDF were built in a workspace copy with no project venvs at all.
- [x] **No finished paper, result or dataset was modified,** and no gate of a real project was approved.

### Known limitations (not blockers)

- [ ] **The hook is a guard rail, not a sandbox.** It does not catch inline code (`python -c exec(...)`), `make` or `npm`, notebooks, a copy of the script outside the project, the user's own terminal, or anything when Python is missing (it fails open). Documented in `references/checkpoints.md`.
- [ ] **`--said` is typed by Claude.** The record is only as truthful as Claude's compliance with the rules.
- [ ] **The run manifest records versions, not snapshots.** Package files and data are not archived. Non-Python interpreters are recorded by name only.

## 3. Real-paper integration test: CVSS/KEV (read-only)

**Method:**
- The number audit ran read-only on the original.
- Everything else ran on a copy in the scratchpad, without the 147 MB of data or the venv.
- `manuscript init` scaffolded the copy (`paper.md` set aside and restored), then `verify-refs`, `check`, `build`, `review` and `build --final` ran on it.
- The original folder is unchanged according to `git status`.

| Area | Result |
| --- | --- |
| References | 10 records in `refs/` load as-is: 8 `verified`, 2 `identifier_resolves` (DataCite DOIs: Zenodo, SSRN). |
| Numbers | 237 match `results.json`, 64 untraced, 57 years, 54 small integers, 4 labels. |
| Draft build | DOCX, HTML and PDF built. The PDF's title page, abstract and 4 figures render correctly. |
| Approval behaviour | `review` was refused with 54 blocking issues, and `build --final` was refused ("manuscript is not started", plus the 54 issues). Both are correct. |

**The 64 untraced numbers, classified:**

| Kind | Examples | Count (approx.) | Action |
| --- | --- | --- | --- |
| Method constants | 7.0, 9.0, 95%, 0.05, 1.96, 2.5/97.5, severity bands 3.9/4.0/8.9 | ~35 | Allow in `numbers.allow` |
| Figures from cited literature | 600 (Koscinski), 300,000 (Denysiuk), 23–32% (Allodi), "30 days" | ~6 | Allow; the tool has no "quoted" category |
| Derived from results | 55%/55.2% flagged, 98.5% (=1−1.49%), 64.4%, 14.7%, "14 points", 99,681 | ~10 | Compute in `analysis.py` or allow |
| **Data facts with no code provenance** | **409,838** NVD records, **1,748** KEV CVEs, **1,753** Physical-vector CVEs, 14,600 and 48,000 CVEs per year, 59% (6 score values), 22.3% Microsoft, 289 vendors | ~12 | **Provenance gap:** not written by any code to `results.json` |

I recounted three of these from the local data files, read-only. **409,838, 1,748 and 1,753 are correct.** The others were not recounted. Nothing is wrong in the paper as far as these checks go; the gap is that these values have no code-backed source.

**Problems found, most important first:**
1. **Paper:** about 12 data facts (above) are not produced by `analysis.py`. If the paper is ever revised, add them to `results.json`.
2. **Tool:** the reference list is typed by hand, not generated from `[@key]`. The tool cannot check that the 10 `refs/` records match the typed list ("0 works cited").
3. **Tool:** `manuscript init` refuses a folder that already has a `paper.md`, so there is no adopt mode for an existing paper.
4. **Tool (fixed at finalisation):** pandoc was available only from the finished papers' venvs. It now comes from the root `.venv`.
5. **Tool:** outside the repository, `research.json` is not found, so the author is empty. Inside the repository it works.
6. **Tool, minor:** "Digital Threats Research and Practice" loses the colon from the Crossref title.
