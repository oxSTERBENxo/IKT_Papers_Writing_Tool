# Blind retrieval evaluation: plan, written before any blind run

Recorded 2026-10-19, after the failure analysis and the fixed-pool ranking comparison on the old benchmark, and
before running any retrieval configuration on the blind fixtures.

## Fixtures

- `specs.json` (16 ideas, 3 negative controls), frozen with `MANIFEST.json` before any target search.
- Claims, queries, design elements and anchors are generated by `build_fixtures.py` from a fixed template.
- Targets (`targets.json`): two web searches per idea with fixed templates ("{method} vs {baseline} {task}
  comparison" and "{method} {task} re-evaluation fair comparison {baseline}"), judged against the relevance
  criteria in `specs.json`, and resolved through arXiv or Crossref so that no identifier is typed from memory.
  Only papers that appear as a result link, or whose identifier appears in the result text, are used. Papers named in
  a result's text without a link or identifier are excluded, so the target lists are incomplete by design.
- Bias that remains: the author of the specs knows much of this literature from training. The template limits how
  much that knowledge can shape the query wording, but not which ideas were chosen. Web search is an independent
  engine, but targets favour what web search ranks highly (often well-cited papers).

## Configurations compared

| Name | Query formulation | Ranking | Notes |
| --- | --- | --- | --- |
| `challenge` | arXiv all-words AND | claim overlap (current default) | reference |
| `challenge_arxiv_any` | arXiv relevance-ranked OR; one 30 s cool-down retry on a rate limit | claim overlap | formulation only |
| `challenge_lexical` | as above | rank fusion over claim and queries | lexical improvements together |
| `challenge_hybrid` | as above | fusion + local embedding list (model2vec `minishlab/potion-retrieval-32M`) | optional dependency |

Sources: arXiv and Crossref, as in the 2026-10-19 regression run. OpenAlex's keyless daily budget was already
used up on the day of the run, and Semantic Scholar returns HTTP 429 without a key; both are excluded so that every
configuration faces the same sources. Citation expansion depends on OpenAlex and Semantic Scholar, so it is mostly
unavailable in every configuration. Limit 10 results per query and source. One shared response snapshot
(`--snapshot`), so identical requests get identical responses in every configuration.

## Metrics

Recall@20, Recall@50, MRR, candidate coverage (share of targets anywhere in the list), mean candidates, HTTP calls,
network requests and runtime. Each miss is labelled `source_unavailable`, `not_in_searched_indexes` or `algorithm`.
Verdicts: the share of positive ideas flagged as having close prior work, and the number of the 5 controls flagged
(2 old, 3 new).

## Decision rule for changing the default

Each change is judged on the blind split against the configuration it extends: `challenge_arxiv_any` against
`challenge`, `challenge_lexical` against `challenge_arxiv_any`, `challenge_hybrid` against `challenge_lexical`.
A change becomes the default only if all of these hold:
1. Recall@50 rises by at least 3 targets;
2. MRR falls by no more than 0.02;
3. it flags no more of the 5 controls than the configuration it extends;
4. it needs no more than 1.5 times the HTTP calls and runtime.

Otherwise it stays available as an option and is documented as experimental. `challenge_hybrid` needs a non-standard
library package, so at most it becomes a recommended option when the package is installed, never the default.
No statistical significance is claimed: with a few dozen targets, differences of a few papers are within noise.
Nothing is tuned after the blind run; any later change needs a new blind set.
